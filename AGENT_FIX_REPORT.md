## ❌ Проблема

**Описание:** Компьютеры, на которых играют клиенты, отображались в интерфейсе как "Свободен" вместо "В игре".

**Причина:** Неправильная логика определения активных сессий.

---

## 🔍 Анализ

### Обращение в поддержку SmartShell

Получена информация от техподдержки:
- Активные сеансы можно получить через `query hostsOverview` с параметром `client_sessions`
- Документация: https://apidoc.smartshell.gg/hostsOverview.html
- Доступные поля: `id`, `started_at`, `finished_at`, `duration`, `elapsed`, `time_left`

### Отладка

Запустили приложение с отладочными логами и обнаружили:

**Формат данных от API:**
```json
{
  "id": 79541292,
  "started_at": "2026-11-02 18:14:16",
  "finished_at": "2026-11-02 21:14:16",  // ⚠️ Есть даже у активных!
  "duration": 10800,
  "elapsed": 5080,
  "time_left": 5712  // ✅ Ключевое поле!
}
```

**Ключевая находка:** 
- У всех сессий (даже активных) присутствует поле `finished_at`
- `finished_at` - это запланированное время окончания, а не фактическое
- **Активность сессии определяется по `time_left > 0`**

---

## ✅ Решение

### 1. Расширен GraphQL запрос

**Было:**
```graphql
client_sessions {
  id
  started_at
  finished_at
}
```

**Стало:**
```graphql
client_sessions {
  id
  started_at
  finished_at
  duration
  elapsed
  time_left  // ← Добавлено
}
```

### 2. Исправлена логика определения статуса

**Было:**
```javascript
const hasActiveSession = host.client_sessions && 
                         host.client_sessions.some(s => !s.finished_at);
```

**Стало:**
```javascript
const hasActiveSession = host.client_sessions &&
                         Array.isArray(host.client_sessions) &&
                         host.client_sessions.length > 0 &&
                         host.client_sessions.some(s => s && s.time_left && s.time_left > 0);
```

### 3. Улучшена надёжность

- Добавлена проверка на массив
- Проверка длины массива > 0
- Проверка существования объекта сессии
- Проверка наличия и значения `time_left`
